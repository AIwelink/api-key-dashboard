# 动态用户类型与权限管理设计

## 目标

权限管理支持新增自定义用户类型。每个类型使用稳定的英文标识和可修改的显示名称，并能配置页面权限。用户创建和编辑页面从数据库动态读取类型，不再依赖前端固定枚举。

API 权限暂不拆分到每个 HTTP 接口。页面权限同时作为对应后端业务接口的权限标识；“API Key 管理”是一个独立权限项，同时控制页面入口和令牌管理接口，当前仅 `owner` 拥有且不可移除。

## 数据模型

继续使用 `app_settings` 集合中 `_id = "role_permissions"` 的文档，避免引入第二份角色数据源。

```json
{
  "_id": "role_permissions",
  "role_order": ["owner", "admin", "maintainer", "operator", "viewer", "support"],
  "roles": {
    "support": {
      "label": "客服",
      "builtin": false,
      "allowed_views": ["todos"],
      "default_view": "todos"
    }
  },
  "updated_at": "...",
  "updated_by": "..."
}
```

约束：

- 角色标识匹配 `^[a-z][a-z0-9-]{0,31}$`，全局唯一，创建后不可修改。
- 显示名称去除首尾空白后长度为 1 到 40 个字符，可修改。
- `owner`、`admin`、`maintainer`、`operator`、`viewer` 为内置类型，`builtin = true`，不可删除。
- 自定义类型创建时无页面权限，`default_view = null`。
- `role_order` 决定权限面板和用户下拉框顺序；新增类型追加到末尾，删除时同步移除。
- `owner` 始终保留用户与权限管理入口以及 `api-tokens` 权限，防止系统失去可恢复的管理员。
- 非 `owner` 的 `api-tokens` 权限在读取和保存时均被移除，不能通过直接调用接口绕过。

启动兼容迁移会为现有五种类型补齐 `label`、`builtin` 和 `role_order`，保留已有 `allowed_views`、`default_view` 以及数据库中合法的自定义类型。

## 后端接口

保留现有接口：

- `GET /api/settings/role-permissions` 返回权限目录、角色顺序及全部角色定义。
- `PUT /api/settings/role-permissions` 修改显示名称、页面权限和默认页面，不允许修改标识或内置状态。

新增接口：

- `POST /api/settings/role-permissions/roles` 创建自定义类型，请求字段为 `id` 和 `label`。
- `DELETE /api/settings/role-permissions/roles/{role_id}` 删除自定义类型。

创建时由后端校验格式、保留名称和重复标识。删除前查询 `users` 集合；存在任何引用该角色的用户时返回 `409 Conflict`。删除内置类型返回 `400 Bad Request`，不存在的类型返回 `404 Not Found`。

用户写入规则：

- `UserCreate.role` 和 `UserUpdate.role` 改为受长度与格式约束的字符串。
- 创建或修改用户时，后端查询当前角色配置，角色不存在则返回 `400 Bad Request`。
- 登录与 `/auth/me` 继续从数据库读取角色权限。
- 历史用户引用不存在角色时按 `viewer` 权限降级，但不会静默改写用户文档。

API Key 规则：

- API Key 管理页面只在当前用户拥有 `api-tokens` 权限时显示。
- 所有令牌列表、创建、修改、撤销和删除接口都使用后端 `api-tokens` 权限依赖。
- 权限归一化保证只有 `owner` 可以拥有 `api-tokens`，因此当前效果为仅 `owner` 可访问。
- 自定义用户类型不加入 API Token 的角色选项；本次只扩展用户账号类型。

所有角色创建、修改和删除操作写入审计日志，记录操作者、角色标识以及变更前后内容。

## 前端交互

权限管理面板增加带加号图标的“添加用户类型”按钮。弹窗包含：

- 显示名称输入框。
- 英文标识输入框，并展示格式错误与重复错误。
- 确认创建和取消操作。

创建成功后，新类型立即出现在权限列表末尾。新类型默认无权限，管理员在同一面板勾选页面并选择默认页面后保存。

内置类型不显示删除操作。自定义类型显示删除图标和确认对话框；若后端返回角色正在使用，页面提示先修改关联用户，不移除当前界面数据。

“API Key 管理”作为权限列表中的普通可见条目，但只有 `owner` 行为勾选且锁定，其他角色显示未勾选且锁定。这样当前限制清晰可见，后续若放开策略也有稳定的权限标识。

用户管理页面加载角色权限配置并据此生成创建与编辑下拉框。显示名称用于界面，英文标识作为提交值。`owner` 的现有分配限制继续保留。

## 权限执行

权限判断只在后端数据库配置上执行，前端隐藏仅用于交互体验。页面权限标识同时用于对应业务路由依赖，不维护单独的逐接口权限清单。

本次新增或调整的 API Key 路由必须绑定 `api-tokens` 权限。现有已绑定页面权限的流量分析与运营管理路由继续使用同一机制。后续业务路由接入权限时沿用页面标识，不扩展成逐 HTTP 方法配置。

## 错误与并发

- 创建角色使用原子条件更新或唯一性复查，避免并发请求产生重复标识。
- 权限更新保留当前数据库中未包含在请求里的角色，避免旧页面覆盖刚创建的类型。
- 删除时先检查用户引用，再使用带角色存在条件的原子更新。用户创建或修改角色后再次读取角色配置；若该角色已被并发删除，则回滚本次用户写入并返回校验错误。这样跨集合操作不会留下引用已删除角色的用户。
- 前端保存失败时保留未提交表单，展示后端错误，不用本地状态假装成功。

## 测试

后端测试：

- 启动迁移补齐内置角色元数据并保留已有权限和自定义类型。
- 成功新增角色；拒绝非法标识、保留标识和重复标识。
- 成功删除未使用的自定义类型；拒绝删除内置类型和正在使用的类型。
- 创建与编辑用户接受数据库中的动态类型，拒绝不存在类型。
- 自定义类型登录后获得数据库配置的页面权限，未知类型降级到 `viewer`。
- API Key 管理接口仅 `owner` 可访问，直接调用也不能绕过。
- 角色创建、更新和删除均写入正确的审计日志。

前端测试：

- 权限面板可新增自定义类型并渲染空权限状态。
- 内置类型无删除按钮，自定义类型可发起删除。
- 正确展示重复、非法和正在使用的错误。
- 用户创建与编辑下拉框使用后端角色列表和显示名称。
- 非 `owner` 不显示 API Key 入口，权限面板中的 API Key 项保持锁定。

运行完整后端测试、前端测试和生产构建作为交付验证。

## 非目标

- 不支持修改角色英文标识。
- 不支持强制删除并批量迁移用户。
- 不支持自定义类型用于 API Token。
- 不支持逐接口、逐 HTTP 方法或读写级别的 API 权限。
- 不在本次引入角色继承、权限组或数据行级权限。
