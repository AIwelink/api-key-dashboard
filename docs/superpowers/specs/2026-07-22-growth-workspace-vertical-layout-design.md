# Growth 工作台纵向布局设计

## 目标

访问流量分析的三个页签不再使用左右分栏的大区块。桌面端和移动端都采用从上到下的操作顺序，同时保留表单内部的紧凑字段网格。

## 页面结构

- 推广链接：新建推广链接表单、筛选区、已生成链接列表依次纵向排列。
- 渠道与活动：新建渠道、渠道列表、新建活动、活动列表依次纵向排列，符合先创建渠道再创建活动的依赖顺序。
- 站点接入：保持单个全宽配置区。
- 页面内容宽度受控并居中；主要工作区不出现左右两块并排的内容。
- 表单字段在桌面端可以多列，在窄屏下自动收敛为单列。

## 行为边界

- 不修改 Growth API、请求 payload、权限、错误处理和刷新逻辑。
- 不增加点击、注册、付费等尚未实现的指标。
- 不引入抽屉、折叠面板或额外步骤交互。

## 验证

- 渲染测试锁定纵向大区块语义。
- 运行 TrafficAnalysisPage 与 App 聚焦测试和前端生产构建。
- 在桌面与 375px 移动视口检查三个页签，确认无横向溢出、重叠或裁切。
