# 飞书待授权身份恢复设计

日期：2026-08-18  
目标分支：`codex/feishu-qr-login`，最终合入 `achernar/dev`

## 1. 问题与目标

当飞书未返回可匹配的组织邮箱时，首次扫码会创建一个无业务权限的待授权临时用户。若该成员随后使用已有本地账号和密码登录，强制绑定流程会发现同一飞书身份已属于临时用户，并以 `identity_already_bound` 拒绝绑定。

本次修复允许已经验证本地密码的用户接管这种从未授权的临时飞书身份，同时保持正常账号之间的绑定冲突保护、唯一身份约束和完整审计。

## 2. 恢复资格

只有同时满足以下条件的身份来源用户可以自动合并：

- `created_by=feishu`；
- `authorization_status=pending`；
- `email_is_placeholder=true`；
- `role=viewer`；
- `status=active`；
- 未设置 `merged_into_user_id`；
- 飞书身份唯一键与本次扫码身份完全一致；
- 目标用户存在、未禁用且尚未绑定其他飞书身份；
- 当前授权会话为密码验证后创建的 `purpose=bind` 会话。

飞书普通扫码登录、已激活用户、非占位邮箱用户、管理员角色用户、已合并用户以及两个正常账号之间的冲突仍然失败。

## 3. 数据模型与无事务策略

生产 MongoDB 不支持多文档事务，因此不在两个用户文档之间移动唯一身份键。临时用户继续保存原始 `feishu_identity.identity_key`，作为唯一身份代理；目标用户只保存不含身份键和外部用户 ID 的安全引用。

临时用户增加：

```text
merged_into_user_id: string
merged_at: datetime
status: "disabled"
```

目标用户的 `feishu_identity` 增加：

```text
source_user_id: string
name: string | null
email: string | null
avatar_url: string | null
bound_via: "password_binding_recovery"
bound_at: datetime
```

`source_user_id` 是本地用户 ID，不是飞书身份 ID。目标用户不复制 `identity_key`、`open_id`、`union_id` 或 `user_id`，因此现有唯一索引保持有效。

## 4. 绑定与登录流程

密码绑定发现身份已经属于另一个用户时：

1. 校验来源临时用户和目标用户是否满足恢复资格。
2. 使用条件更新将来源用户标记为已合并和禁用，指向目标用户。
3. 使用条件更新为目标用户写入安全身份引用。
4. 若目标写入发生并发冲突，重新读取双方状态：已经形成相同代理关系则视为幂等成功，否则保持冲突失败。
5. 写入 `auth.feishu.pending_identity_merged` 审计，只记录两个本地用户 ID、结果码和绑定方式。

后续飞书扫码按唯一身份键命中来源用户后：

- 若存在 `merged_into_user_id`，读取并校验目标用户；
- 更新目标用户的最后飞书登录时间和安全展示字段；
- 返回目标用户并签发其原有角色与权限的本地 JWT；
- 不再为来源临时用户签发 JWT。

后续密码登录目标用户时，`source_user_id` 被视为有效飞书绑定，不再触发重复扫码。

## 5. 失败恢复与安全边界

如果来源代理写入成功但目标引用写入失败，下一次相同密码绑定会识别未完成的同目标代理并补齐目标引用。若来源指向其他目标、目标已有其他身份引用或任一资格字段不匹配，则拒绝自动修复。

禁用或删除目标用户不会使来源临时用户重新可登录。代理解析发现目标缺失或禁用时返回明确认证失败，并保留审计上下文。

用户列表不展示已合并的来源临时用户，避免管理员重复分配权限；数据库记录和审计日志继续保留。

## 6. 当前数据修复

代码部署后使用同一恢复服务修复当前 Owner：将现有待授权临时飞书用户标记为代理并关联 Owner，在 Owner 上写入安全引用。修复脚本必须使用精确的来源和目标本地用户 ID、重复执行幂等，并在执行前后打印不含飞书身份值的状态摘要。

## 7. 测试与验收

后端测试覆盖：

- 符合条件的待授权临时身份可被密码账号恢复；
- 正常、已授权、非占位邮箱和非 viewer 来源不能被接管；
- 来源已指向同一目标时可以补齐并幂等成功；
- 来源指向其他目标时失败；
- 后续飞书登录通过代理返回目标用户；
- 目标禁用或不存在时拒绝登录；
- 密码登录识别代理绑定并直接签发 JWT；
- 用户列表隐藏已合并来源；
- 审计不包含 `identity_key`、`open_id`、`union_id` 或 access token。

验收标准：当前 Owner 可以同时使用密码和飞书登录；待授权临时用户不再出现在待分配列表；其他成员遇到同类场景时可以在验证本地密码后安全恢复；正常账号之间仍不可重新绑定。
