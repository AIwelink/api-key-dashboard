# 运营收入、内部人员邮箱识别与概览改版设计

## 1. 目标

本次调整统一解决三个问题：

1. AIWeLink 与 AIGCLink 使用不同的收入口径，并从运营概览移除净收入。
2. 内部人员按邮箱配置，系统自动识别对应的业务用户 ID。
3. 运营概览合并重复趋势表，并用站点运营对比替换低价值的账号明细。

本次不新增账号详情页，不改变运营站点个人权限规则，也不改变充值、退款和额度事件的原始事实表。

## 2. 收入口径

### 2.1 AIWeLink

AIWeLink 收入继续使用已分类的实际现金收入：

- 成功支付订单按实收 CNY 计入收入；
- 销售用途兑换码和余额调整按运营人员填写的实收 CNY 计入收入；
- 推广、内部使用、补偿和其他非现金额度不计收入。

### 2.2 AIGCLink

AIGCLink 收入按普通用户在统计周期内的实际消耗计算：

```text
AIGCLink 收入 CNY = 普通用户消耗余额单位 / 事实发生时生效的 balance_units_per_cny
```

实现中直接汇总使用事实上的 `cost_cny`。当前 AIGCLink 换算比例为 1，因此收入数值与消耗额度一致；若以后调整比例，历史事实仍按其已绑定的有效比例计算。

- 只计算普通用户消耗；
- 内部人员消耗正常进入调用量和消耗量，但收入为 0；
- “全部用户”视图包含内部人员的调用和消耗，但 AIGCLink 收入仍只来自普通用户；
- AIGCLink 的充值现金流水不再重复计入收入；
- 退款继续作为独立指标展示，不从收入中生成“净收入”指标。

### 2.3 实时与缓存一致性

实时汇总 SQL 和小时/日聚合必须使用同一口径。

为使已有缓存立即可用，趋势查询读取 AIGCLink 历史时间桶时，收入从同时间桶的普通用户 `cost_cny` 推导；新生成的聚合记录也按新口径写入 `gross_income_cny`。AIWeLink 仍读取现金收入聚合。

API 暂时保留 `net_income_cny` 字段以避免破坏兼容客户端，但管理面板不再展示或依赖该字段。

## 3. 内部人员邮箱识别

### 3.1 配置方式

运营人员创建内部人员时填写：

- 站点；
- 邮箱；
- 标记原因；
- 生效时间；
- 可选失效时间。

业务用户 ID 不再由运营人员填写。识别成功后只读展示。

邮箱保存前执行首尾空格清理和小写标准化。同一站点不能重复配置相同的标准化邮箱。

### 3.2 数据结构

`growth.internal_users` 增加：

- `email TEXT`：标准化邮箱；
- `recognized_at TIMESTAMPTZ`：最近一次成功绑定时间。

`external_user_id` 改为允许为空：

- 为空表示“待识别”；
- 非空表示“识别成功”。

新增 `(site_id, lower(email))` 的条件唯一索引。现有记录继续保留原业务用户 ID；能够从 `account_label` 确认邮箱的记录可迁移邮箱，不能确认的记录保持兼容状态，不阻塞启动迁移。

### 3.3 识别流程

创建配置后，Growth PostgreSQL 先在 `ops_user_snapshots` 中按站点和标准化邮箱查找：

```text
lower(trim(snapshot.account_label)) = internal_user.email
```

- 唯一匹配：写入业务用户 ID 和 `recognized_at`，状态为“识别成功”；
- 没有匹配或出现多个同邮箱账号：保存配置，状态为“待识别”，不任意绑定；
- 邮箱修改：清除旧业务用户 ID 和识别时间，重新执行识别。

每次站点用户快照同步时，对待识别配置再次匹配。匹配成功后持久化业务用户 ID，并将对应快照标记为内部人员。后续归类优先使用已保存的业务用户 ID，避免源站邮箱变化破坏已经建立的身份关系。

### 3.4 API 与界面

内部人员列表返回：

- `email`；
- `recognition_status`：`pending` 或 `recognized`；
- `external_user_id`；
- `recognized_at`；
- 原有站点、原因和生效区间。

内部人员表格显示：站点、邮箱、识别状态、业务用户 ID、识别时间、原因、生效时间和失效时间。查询同时匹配邮箱与业务用户 ID。

## 4. 运营概览结构

### 4.1 汇总指标

保留：

- 注册用户；
- 活跃用户；
- 成功调用；
- 付费用户；
- 收入；
- 退款。

删除“净收入”。原“流水收入”统一命名为“收入”。

### 4.2 运营趋势

“收入趋势”和“用户活动趋势”合并为一张按时间桶和站点排列的运营趋势表：

```text
时间 | 站点 | 注册 | 活跃 | 成功调用 | 消耗额度 | 付费用户 | 收入 | 退款
```

48 小时以内按小时汇总，更长周期按天汇总。站点、用户群体和统计周期筛选继续作用于整张表。

### 4.3 站点运营对比

删除概览页的账号运营明细，替换为每站点一行的站点运营对比：

```text
站点 | 注册用户 | 活跃用户 | 成功调用 | 消耗额度 | 付费用户 | 收入 | 退款 | 人均消耗 | 付费率
```

计算规则：

- 人均消耗 = 消耗额度 / 活跃用户数；活跃用户为 0 时显示 0；
- 付费率 = 付费用户数 / 活跃用户数；活跃用户为 0 时显示 0%；
- AIGCLink 收入遵循普通用户消耗口径；
- 当前用户群体筛选仍控制注册、活跃、调用、消耗和付费等指标；选择“全部用户”时，AIGCLink 收入依然排除内部人员。

后端在现有汇总响应中增加当前周期的 `site_breakdown`，避免前端通过时间桶累加活跃用户而产生重复计数。

## 5. 错误与兼容处理

- 待识别内部人员不是错误，列表稳定显示“待识别”；
- 邮箱格式非法或同站点重复时拒绝保存并返回明确错误；
- 源站暂时不可用时不清除已经识别的业务用户 ID；
- 识别成功后源站邮箱变化，不自动解绑；只有运营人员修改配置邮箱时才重新识别；
- 老版本 API 使用的 `net_income_cny` 暂时保留，但新前端不读取；
- 运营站点权限继续约束所有查询和写入。

## 6. 测试与验收

### 6.1 收入

1. AIWeLink 普通用户支付 100 CNY，收入为 100 CNY。
2. AIGCLink 普通用户消耗 20 余额单位且比例为 1，收入为 20 CNY。
3. AIGCLink 内部人员消耗 20 余额单位，消耗为 20，收入为 0。
4. “全部用户”同时包含普通和内部消耗，但 AIGCLink 收入只等于普通用户消耗。
5. 概览和趋势均不显示净收入。

### 6.2 邮箱识别

1. 创建已存在邮箱的内部人员配置后立即显示“识别成功”和业务用户 ID。
2. 创建尚不存在的邮箱后显示“待识别”。
3. 后续同步出现该邮箱时自动变为“识别成功”。
4. 邮箱匹配忽略大小写和首尾空格。
5. 同一站点重复邮箱被拒绝，不同站点可使用相同邮箱。

### 6.3 概览

1. 两个旧趋势区被一张运营趋势表替换，并按时间和站点显示完整指标。
2. 账号运营明细被站点运营对比替换。
3. 人均消耗和付费率分母为 0 时不出现异常值。
4. 单站点权限用户只看到授权站点，双站点权限用户可查看合并结果。
