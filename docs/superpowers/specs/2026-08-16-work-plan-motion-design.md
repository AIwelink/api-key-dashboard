# 工作计划页流畅动效设计

## 目标

工作计划页是团队高频查看和快速编辑的工具。动效的任务是让状态变化连续、可预测、容易追踪，而不是增加装饰。当前页存在加载时白屏、刷新时内容跳动、抽屉与详情层级切换不连贯等体验问题。本设计采用 AIwelink 主页 `main` 分支的分阶段揭示、防闪烁加载和短时过渡原则，但针对排班表的密集数据做性能收敛。

## 已确认方向

采用 A「入场与层级」：内容从左到右、从上到下以短距离位移和透明度变化进入，时间条以左侧为锚点展开，抽屉从右侧平滑进入。首次进入和数据刷新都使用动效，但所有动画保持短、轻、可中断。

不采用主页的全屏 intro、粒子背景、持续呼吸动画和大面积 blur。工作计划页需要在刷新期间继续读取已有内容，也不能让持续运动干扰时间比较。

## 视觉基线

### 色彩

沿用现有管理面板和工作计划页色彩，不引入主页的黑底、荧光黄或粉色渐变：

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| Canvas | `#fffbfc` | 页面背景 |
| Panel | `#ffffff` | 排班表、抽屉和控件表面 |
| Text | `#2d2028` | 主文案和时间 |
| Muted | `#7a6570` | 辅助信息 |
| Accent | `#d85c82` | 当前系统强调色、焦点和短反馈 |
| Work green | `#27845a` | 生效工作时间和成功状态 |
| Neutral gray | `#899299` | 已取消历史 |

动画不改变计划语义颜色。状态反馈优先使用透明度、位移和局部边框高亮，避免红色覆盖整个页面。

### 字体与排版

继续使用现有页面字体栈和字号，不在本次工作中替换字体。时间、数量和优先级保持 `font-variant-numeric: tabular-nums`，确保动画前后数字宽度稳定。任何动画容器都必须允许文本换行，不通过放大字体制造动势。

### 动效 token

```css
--wp-motion-fast: 160ms;
--wp-motion-standard: 220ms;
--wp-motion-drawer: 280ms;
--wp-motion-page: 560ms;
--wp-motion-stagger: 40ms;
--wp-ease-enter: cubic-bezier(.16, 1, .3, 1);
--wp-ease-state: cubic-bezier(.22, 1, .36, 1);
--wp-ease-exit: cubic-bezier(.4, 0, 1, 1);
```

进入使用 `opacity` 与 `transform: translate3d(0, 8px, 0)`；退出使用更短的透明度和位移。时间条使用 `transform: scaleX()`，以左侧为 transform origin。禁止动画 `height`、`width`、`top`、`left`、`box-shadow`、大面积 `filter: blur()` 等容易触发重排或高成本绘制的属性。

## 页面结构与入场编排

```text
工作计划
  ├─ 标题和主操作              0ms
  ├─ 概览四项                   40ms
  ├─ 日期范围和筛选             100ms
  ├─ 错误/过期提示（如有）       140ms
  └─ 排班表                     180ms
       ├─ 表头                  180ms
       ├─ 前三行成员             220/260/300ms
       └─ 其余成员               260ms 后统一进入
```

错峰只发生在首屏可见内容，成员行数量超过三行后统一进入，避免几十行计划产生长尾动画。进入动画不能阻塞点击；动画尚未结束时控件仍可获得焦点。

刷新时不重播整页入场：保留旧排班表，顶部显示一条从左向右的细进度线；新数据到达后，发生变化的概览数字和时间条做一次局部反馈。

## 状态与交互设计

| 状态 | 动效 | 体验约束 |
| --- | --- | --- |
| 首次加载超过 100ms | 轻量骨架/加载状态淡入 | 100ms 内不显示，避免闪烁 |
| 已有内容刷新 | 顶部进度线 `scaleX` 循环 | 不覆盖旧内容，不改变滚动位置 |
| 日期范围/成员筛选 | 当前结果淡出 80ms，新结果错峰进入 | 保留工具栏和筛选值 |
| 时间条新增 | 从左锚点 `scaleX(0 → 1)` | 不改变行高，不使用持续动画 |
| 时间条更新 | `transform` 平滑到新位置和长度 | 取消段保持灰色，语义不靠动画表达 |
| 成功创建/取消/编辑 | 受影响时间条一次绿色/灰色边框闪现 | 反馈结束后回到正常颜色 |
| 加载失败/过期 | 提示条短距离进入 | 不使用整页红色背景，不遮挡排班表 |
| 填写计划抽屉 | 遮罩淡入，面板从右侧 `translateX(18px)` 进入 | 关闭速度略快，保留焦点管理 |
| 我的安排抽屉 | 同一套抽屉过渡 | 与填写抽屉不可同时竞争焦点 |
| 计划详情 | `opacity + translateY(6px)` | 关闭后焦点回到原时间条 |
| 优先级弹层 | `opacity + translateY(4px) + scale(.98 → 1)` | 不穿透成员列，不改变表格滚动 |
| 更多日期 | 内容区域淡入并展开 | 不产生红色 hover 背景或页面溢出 |
| 确认取消 | 遮罩淡入、对话框短距离进入 | 操作中锁定确认按钮，避免重复提交 |
| Toast 成功/失败 | 从右上短距离进入，自动退出 | 文案和按钮状态一致 |

## React 与 CSS 边界

### React 负责

- 提供 `loading`、`refreshing`、`mutationBusy` 等稳定状态类和 `aria-busy`。
- 使用一次性的页面入场 epoch，让首屏编排只播放一次；筛选和刷新走独立的轻量状态类。
- 在数据变化时计算受影响的 segment key，给局部时间条添加一次性 feedback class，动画结束后清除。
- 抽屉和弹层继续使用现有焦点管理与 handoff 逻辑；动画只改变可见状态，不改变打开/关闭 API。

### CSS 负责

- 所有过渡、错峰延迟、进入/退出关键帧和 reduced-motion 覆盖。
- 抽屉、详情、更多日期和优先级弹层保持稳定尺寸、层级和滚动边界。
- 时间条只动画 transform/opacity，避免布局重排。

不引入 GSAP、Framer Motion 或其他新依赖。Vite 的 CSS 构建已足够完成本方案，React 只编排状态，不用 `requestAnimationFrame` 驱动每个成员行。

## 性能与可访问性

- 只对当前可见的页面层和首屏最多三条成员行做错峰。
- 不对整张表使用 blur、filter、backdrop-filter 或持续循环动画。
- `will-change` 只在打开/关闭和时间条反馈的短时间内使用，动画完成后恢复。
- 刷新不清空数据，不触发滚动回顶部，不重复创建大量 DOM。
- 支持 `prefers-reduced-motion: reduce`：直接显示最终状态，关闭持续动画，保留必要的 loading 文案和 `aria-live`。
- 保持键盘焦点、`aria-busy`、`role=status` 和现有对话框焦点返回行为。
- 页面不存在横向溢出；移动端抽屉和更多日期区域只在自身容器内滚动。

## 测试与验收

### 单元与组件测试

- 动效 token 和 reduced-motion 规则存在且选择器作用域为工作计划页。
- 首次加载、刷新、筛选、抽屉、更多日期和详情状态有对应 class/ARIA 状态。
- 刷新期间旧排班数据仍在 DOM 中，刷新结束后只更新变化段。
- 时间条点击、编辑、取消和焦点返回行为不因动画改变。
- 重复点击提交不会生成第二次 mutation。

### 构建与浏览器验收

- `npm test`：工作计划相关组件和样式测试全部通过。
- `npm run build`：TypeScript 与 Vite 生产构建通过。
- 使用浏览器检查桌面和手机尺寸：首次进入、日期筛选、刷新、打开填写计划、展开更多日期、打开详情、打开优先级、取消确认、成功反馈。
- 检查控制台无 React/Vite 错误，无页面级横向溢出，无内容重叠。
- 分别在正常动效和 reduced-motion 下检查最终状态可达且焦点顺序不变。

## 设计自检

本方案的唯一视觉记忆点是“计划轨迹从左侧展开并与页面层级同步进入”，它直接来自排班表的时间轴语义，而不是通用的卡片浮动或装饰性粒子。主页的黑底、粒子和持续光效被明确排除，因为它们会增加工作台卡顿和认知噪音。其余界面保持现有的浅色、窄圆角、线性排版和紧凑信息密度，确保动效服务于扫描和操作。
