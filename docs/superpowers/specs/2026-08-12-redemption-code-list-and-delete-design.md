# 兑换码列表与安全删除边界设计

## 1. 目标

在运营管理的“额度与兑换码”页面增加真实兑换码列表，让有权限的运营人员可以：

- 查看所有已授权 API 站点的兑换码；
- 区分兑换码由管理面板还是 API 站点创建；
- 优先看到当前登录账号创建的兑换码；
- 临时查看单个兑换码明文；
- 在上游提供原子条件删除后，开放单个或批量删除未使用兑换码。

本功能不改变现有生成流程，不在 Growth PostgreSQL、MongoDB 审计或浏览器持久存储中新增兑换码明文副本。

## 2. 数据边界

### 2.1 权威数据源

API 站点是兑换码当前状态和明文的权威数据源。列表和明文查看通过已验证的站点管理 API 完成。

Growth PostgreSQL 的 `growth.redemption_batches` 只用于：

- 识别管理面板创建的兑换码；
- 关联创建账号；
- 保留批次用途、备注、创建时间和操作结果；
- 通过远端兑换码 ID、不可逆哈希和掩码完成关联。

Growth 批次继续作为操作审计和运营归因记录存在，不保存明文。

### 2.2 明文生命周期

常规列表响应不包含明文，只返回掩码。owner/admin 点击“查看”后，后端实时从对应 API 站点读取单个兑换码，并仅在该次响应中返回明文。

明文不得写入：

- Growth PostgreSQL；
- MongoDB 审计日志；
- 后端应用日志；
- 前端 localStorage、sessionStorage 或其他持久缓存。

前端关闭查看弹窗、切换页签或卸载页面时清除内存中的明文。

## 3. 列表范围与字段

列表展示所选 API 站点中的全部兑换码，包括：

- 通过运营管理页面生成的兑换码，标记为“管理面板创建”；
- 通过 API 站点自身后台或其他入口生成的兑换码，标记为“API站点创建”。

每行显示：

| 字段 | 说明 |
| --- | --- |
| 兑换码 | 默认显示掩码 |
| 站点 | AIWeLink、AIGCLink 等业务站点 |
| 额度 | API 站点返回的兑换码额度 |
| 状态 | 未使用、已使用、已过期、已禁用等 |
| 来源 | 管理面板创建或 API站点创建 |
| 创建账号 | 管理面板账号；无法关联时显示 `-` |
| 创建时间 | API 站点记录的创建时间 |
| 使用账号 | 已使用时显示业务用户信息 |
| 使用时间 | 已使用时显示兑换时间 |
| 操作 | owner/admin 可临时查看明文 |

查询栏支持：

- 站点；
- 状态；
- 来源；
- 兑换码或使用账号关键词。

为了避免完整兑换码进入管理面板和 API 站点访问日志，列表查询使用请求体传输搜索词，后端在内存中筛选，不把搜索词透传到远端 GET URL。后端最多读取 10 页、10000 条远端记录，达到上限时返回 `truncated=true`。

列表响应采用显式字段白名单，只返回页面所需的兑换码字段和使用账号邮箱。远端的 `notes`、完整 `user`、`group` 以及未来新增字段均不自动透传。

## 4. 来源关联与排序

### 4.1 来源关联

管理面板生成成功时，`source_batch_id` 保存 Sub2API 返回的兑换码 ID。现有批次可能包含逗号分隔的多个 ID。列表查询时，后端将远端兑换码 ID 与已授权站点的 Growth 批次进行关联。

关联成功时：

- `origin=management_panel`；
- 显示批次的 `requested_by` 为创建账号标识；
- 返回 `created_by_current_user` 布尔值。

未关联到 Growth 批次时：

- `origin=api_site`；
- 创建账号显示 `-`；
- `created_by_current_user=false`。

### 4.2 排序

非“待分类”页面涉及的兑换码列表使用以下固定顺序：

1. 当前登录账号通过管理面板创建的兑换码；
2. 其他管理面板账号创建及 API 站点创建的兑换码；
3. 每组内部按 `created_at DESC` 排列；
4. 创建时间相同时按远端兑换码 ID 倒序，保证分页顺序稳定。

排序在后端完成，前端不重新排序。为保证“本人优先”跨分页正确，后端会从选定站点读取符合筛选条件的远端数据，完成关联和排序后再返回请求页。V1 对单次读取设置明确上限；达到站点上限时返回可识别的截断标志，不能静默遗漏。

## 5. 权限

所有接口继续使用 `operations-management` 页面权限和现有 `operations_site_ids` 站点权限。

| 能力 | owner/admin | 只读运营角色 |
| --- | --- | --- |
| 查看掩码列表 | 是 | 是 |
| 查看完整明文 | 是 | 否 |
| 单条删除 | 暂不可用 | 暂不可用 |
| 批量删除 | 暂不可用 | 暂不可用 |

后端必须独立执行角色和站点权限校验，不能依赖前端隐藏按钮。

## 6. 删除安全边界

当前 Sub2API 官方单删和批删接口最终执行无状态条件的硬删除。即使管理面板先读取并确认 `status=unused`，兑换仍可能发生在状态检查和删除之间，造成已使用记录被硬删除并破坏对账。这一 TOCTOU 竞态无法通过重复读取彻底消除。

因此 V1 不展示选择框和删除控件；删除端点固定返回 `capability_unavailable`，不调用远端删除。客户站点 PostgreSQL 连接继续保持只读，不绕过 Sub2API 直接写业务数据库。

只有上游提供单次数据库事务中的原子 `delete-if-unused` 或等价能力，并返回明确的成功、冲突和部分失败结果后，才重新开放删除。

明文查看操作写入 MongoDB 审计，只记录操作账号、站点、远端兑换码 ID 和掩码，不记录返回明文。

## 7. 后端接口

### 7.1 列表

`POST /api/operations/redemption-codes/query`

请求体：

- `site_id`：V1 必填，避免跨站点远端查询语义不清；
- `page`：默认 1；
- `page_size`：默认 20，最大 100；
- `status`：可选；
- `origin`：`management_panel` 或 `api_site`，可选；
- `search`：可选，最大 100 字符。

响应包括 `items`、`total`、`page`、`page_size`、`pages` 和 `truncated`。每个 item 仅含掩码和公开字段。

### 7.2 临时查看

`GET /api/operations/redemption-codes/{site_id}/{code_id}/reveal`

仅 owner/admin 可调用。响应包含 `code_id`、`code` 和 `fetched_at`。响应设置 `Cache-Control: no-store`。

### 7.3 单条删除能力探测

`DELETE /api/operations/redemption-codes/{site_id}/{code_id}`

仅 owner/admin 可调用。当前固定返回 409 和 `capability_unavailable`，且不调用远端删除接口。

### 7.4 批量删除能力探测

`POST /api/operations/redemption-codes/batch-delete`

请求体包含一个 `site_id` 和去重后的 `code_ids`，数量限制为 1 至 100。当前固定返回 409 和 `capability_unavailable`，且不调用远端删除接口。

## 8. 前端交互

兑换码列表位于“额度与兑换码”页的换算比例上方。查询控件保持现有横向查询栏样式，数据区使用现有全宽表格，不增加左右分栏或嵌套卡片。

交互规则：

- 切换站点、状态或来源后回到第一页并重新查询；
- 关键词按“查询”或 Enter 提交；
- 查看明文使用弹窗，关闭时清除明文状态；
- 列表请求使用请求序号和站点校验，过期响应不能覆盖当前站点；
- 明文查看响应绑定请求序号、站点、页签和当前写权限，状态变化后不能重新打开弹窗；
- 所有角色均不显示选择框和删除控件；
- 只读角色不显示明文查看控件。

## 9. 错误处理

- API 站点不可用：返回 502，并保留当前列表，前端显示刷新失败提示；
- 站点未配置或版本不支持：返回 `capability_unavailable`；
- 兑换码不存在：返回 404；
- 当前版本删除：返回 409 和稳定错误码 `capability_unavailable`；
- 批量请求混合站点或超过 100 条：返回 400；
- 权限不足：返回 403；
- Growth 关联查询失败：列表请求返回 503，不把所有记录误标为 API 站点创建。

## 10. 测试与验收

后端测试覆盖：

- Sub2API 列表和单条读取契约；
- 列表响应不泄露明文；
- 列表字段白名单不透传远端内部字段；
- 管理面板与 API 站点来源识别；
- 当前账号优先、组内创建时间倒序和稳定排序；
- owner/admin 与只读角色权限；
- 站点权限隔离；
- 审计不含明文；
- 删除端点不调用不安全的远端硬删除；
- 远端 404 保持为 404。

前端测试覆盖：

- 查询栏、列表字段、来源标签和分页；
- 只读角色不显示敏感操作；
- 明文弹窗关闭后清理；
- 过期列表和明文响应被丢弃；
- 删除控件保持隐藏；
- 当前账号优先结果按后端顺序展示。

验收流程：

1. 在管理面板为 AIWeLink 生成两个兑换码；
2. 在 AIWeLink 原生后台生成一个兑换码；
3. 列表显示三条，来源标签正确；
4. 当前登录账号创建的两条置顶，并按创建时间倒序；
5. 点击查看能临时看到明文，刷新页面后恢复掩码；
6. 使用其中一条兑换码；
7. 页面不显示单删或批删入口；
8. 直接调用删除端点返回 `capability_unavailable`，API 站点记录不发生变化；
9. Growth 批次和 MongoDB 审计均不包含明文。
