# 运营生命周期与商业指标设计

## 1. 目标

在现有运营概览的注册、活跃、调用、消耗和收入之外，增加一组口径明确、可追溯的生命周期指标，让运营人员能同时判断：

1. 新用户是否完成激活并持续使用；
2. 用户是否从注册或活跃转化为付费；
3. 余额、订阅和企业后付费三种商业模式分别贡献了什么；
4. 哪些用户正在沉默、流失或回流；
5. AIGCLink 的计费金额是否与业务数据看板保持一致。

首版不建设预测 LTV、回款率、合同应收账龄或营销来源归因。这些指标需要可靠的合同、到账或推广归因事实后再扩展。

## 2. 统一行为口径

所有站点和商业模式使用同一套行为定义：

- **成功调用**：业务调用事实中的 `successful_call_count > 0`；失败请求、充值、兑换、订阅续费和每日配额刷新都不算使用。
- **24 小时激活**：注册后 24 小时内至少有一次成功调用。
- **7 日激活**：注册后 7 x 24 小时内至少有一次成功调用。
- **注册 Cohort 留存**：按 `Asia/Shanghai` 注册自然日分组，D1、D3、D7、D14、D30 对应目标自然日内至少一次成功调用。
- **未成熟 Cohort**：尚未到达目标观察日时，该留存格为空，不进入该指标分母。
- **流失预警**：曾经成功调用，但截至查询窗口结束已连续 14 天没有成功调用，且未达到 30 天。
- **使用流失**：曾经成功调用，但截至查询窗口结束已连续 30 天没有成功调用。
- **回流**：查询窗口内发生成功调用，且该用户本次调用与上一次成功调用间隔至少 30 天。

普通用户和内部人员继续使用现有 `segment` 过滤。默认只看普通用户。

## 3. AIWeLink 商业口径

### 3.1 付费身份

- **累计付费用户**：截至窗口结束，至少存在一笔可核验实收大于 0 的销售事实。
- **本期付款用户**：窗口内至少存在一笔可核验实收大于 0 的销售事实。
- **活跃付费用户**：累计付费用户中，窗口内有成功调用的用户。
- **有效付费用户**：窗口内拥有有效付费订阅，或累计付费且当前仍有余额权益的用户。
- **付费状态未知**：使用过尚未分类的历史兑换码，且没有其他可核验实收事实的用户。

历史兑换码不通过额度大小、名称或备注猜测是否付费。即使额度小于 1000 美元也不能据此判断赠送或销售。

### 3.2 充值与订阅

- 完成的余额订单计充值和现金收入。
- 明确分类为 `sale` 的余额型兑换码或手工加额计充值；只有录入可核验实收金额时才计现金收入和确认付费身份。
- 订阅订单计现金收入和本期付款；每日刷新订阅配额不计充值、付款或复购。
- 推广、内部、补偿和其他非现金额度不计充值、收入或付费身份。
- 同一销售收款与兑换入账只确认一次现金收入。

### 3.3 收入

- **现金收入**：按实际收款日确认完成订单和已录入实收的销售事实。
- **订阅摊销收入**：完成订阅订单的实收金额按订单订阅天数，从完成时间起逐日线性分摊；用于观察服务期经营表现，不替代现金收入。
- **余额消耗**：作为使用价值单独统计，不重复确认收入。

## 4. AIGCLink 商业口径

AIGCLink 是企业后付费模式，不使用充值、兑换码或转账记录推导运营收入。

- `quota_data.quota` 是数据看板已按模型、Token 和价格规则计算后的原始计费额度。
- 展示金额为 `quota_data.quota / QuotaPerUnit`，不再叠加 Growth 余额换算比例，避免配置变化改写看板收入。
- **计费客户**：窗口内至少一条成功调用的已计价金额大于 0 的普通企业用户。
- **调用计费收入**：窗口内普通企业用户的已计价调用金额之和。
- 免费、折扣后为零和内部人员调用仍计调用量，但不计收入和计费客户。
- AIGCLink 不展示充值率、余额复购率或本期付款收入。没有可靠企业转账事实前，不计算回款率。

同步时保留 `model_name`，以支持模型收入排行；用户维度使用现有用户快照标签。

## 5. 转化率

所有比例同时返回分子、分母和比率；分母为 0 时比率为 `null`，不显示为 0%。

- **7 日新客付费转化率**：已成熟 7 天的注册用户中，注册后 7 天内首次形成付费/计费事实的用户占比。
- **30 日新客付费转化率**：已成熟 30 天的注册用户中，注册后 30 天内首次形成付费/计费事实的用户占比。
- **活跃用户付费率**：窗口内活跃用户中，累计付费用户或 AIGCLink 计费客户的占比。
- **本期付款率**：AIWeLink 窗口内活跃用户中，本期真实付款用户占比；AIGCLink 返回不适用。

## 6. 数据模型与同步

Growth PostgreSQL 增加：

1. `usage_facts.billed_amount_cny`：源系统已经计算完成的调用计费金额；AIGCLink 直接写入，AIWeLink 为 0。
2. `usage_facts.model_name`：调用模型，源系统没有时为空字符串。
3. `usage_facts.token_count`：源系统已聚合的 Token 数；源系统没有时为 0。
4. `subscription_entitlements`：站点、用户、源记录、开始时间、结束时间、状态和更新时间，用于判断窗口内有效订阅。

两类源适配器每次同步读取全部订阅权益快照并按站点替换，保证过期、撤销和续期状态不会残留。调用事实继续增量同步。

聚合版本升级后全量回补 AIGCLink 历史 `quota_data`，使历史计费金额和模型维度使用同一口径。AIWeLink 的历史支付回补逻辑继续保留。

## 7. API

新增：

```text
GET /operations/lifecycle?site_id=&segment=&range=&start_at=&end_at=
```

响应包含：

- `summary`：激活、转化、付费分层、预警、流失和回流；
- `retention`：按站点和注册日排列的 Cohort 行；
- `site_breakdown`：每站适用的商业模式、收入与用户指标；
- `model_breakdown`：AIGCLink 模型调用量、Token、计费金额和占比；
- `customer_breakdown`：高价值客户调用量和计费金额排行；
- `window` 和 `generated_at`。

接口复用现有站点权限、用户分群、时间范围和响应缓存。任何未授权站点不得出现在汇总或明细中。

## 8. 页面

运营概览保留现有时间、站点和用户范围筛选，并增加四个紧凑区域：

1. **生命周期指标**：24 小时激活率、7 日激活率、D7 留存、活跃用户付费率、本期付款率、流失预警、使用流失、回流；
2. **付费与计费分层**：累计付费、有效付费、活跃付费、本期付款、付费未知，以及 AIWeLink/AIGCLink 的口径标签；
3. **留存 Cohort**：注册日期、站点、人数和 D1/D3/D7/D14/D30；未成熟格显示 `--`；
4. **价值排行**：AIGCLink 模型和企业客户的调用计费排行。

已有运营趋势继续展示注册、活跃、成功调用、消耗、付费用户、收入和退款。站点收入标签明确区分 AIWeLink 的现金收入与 AIGCLink 的调用计费收入。

## 9. 数据质量和失败处理

- 付费状态未知人数单独展示，绝不并入确认付费用户。
- 缺少用户快照的调用事实不进入用户型指标，并由现有同步质量机制保留排查线索。
- AIGCLink `quota` 缺失或非法时写入 0 计费金额，但保留调用量。
- 订阅缺少有效结束时间时，不猜测长期有效；状态为 active 且有明确窗口才算有效权益。
- 源数据库读取或 Growth 写入失败时整次同步回滚，聚合版本不前进。

## 10. 验证

- 单元测试覆盖两站适配器、聚合 SQL、成熟 Cohort、激活边界、14/30 天流失、30 天回流、未知兑换码和站点差异化付费口径。
- 路由测试覆盖权限、查询参数和响应结构。
- 前端测试覆盖未成熟留存、空分母、站点不适用指标和价值排行。
- 运行后端全量测试、前端全量测试和生产构建。
- 用只读 SQL 对比 AIGCLink 选定时间窗口的 `SUM(quota) / QuotaPerUnit` 与运营接口计费收入。
