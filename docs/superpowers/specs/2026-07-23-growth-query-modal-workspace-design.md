# Growth 查询列表与创建弹窗设计

## 目标

访问流量分析工作台改为查询和列表优先。推广链接、渠道和活动的创建表单不再长期占据页面空间，而是由列表页右上角的新建按钮打开居中大弹窗。站点接入继续使用页内表单。

本设计只采用已确认的交互结构，不参考讨论阶段低保真草图的视觉样式。实际界面必须复用当前管理面板的颜色、控件、间距和列表风格。

## 顶部页签

顶部使用四个平级页签，顺序固定为：

1. 推广链接
2. 渠道管理
3. 活动管理
4. 站点接入

原“渠道与活动”页签拆除。渠道和活动各自拥有独立的查询、列表和创建入口。

## 页面结构

### 推广链接

- 页面主体是推广链接查询区和结果列表。
- 查询条件包括站点、渠道、活动、状态和关键词。
- 右上角提供“新建推广链接”按钮。
- 点击按钮后，在弹窗中显示现有推广链接创建字段和扩展维度。
- 渠道与活动仍保持联动；没有活动的渠道可以选中，但不能提交推广链接。

### 渠道管理

- 页面主体是渠道查询区和渠道列表。
- 查询条件包括关键词和状态。
- 右上角提供“新建渠道”按钮。
- 点击按钮后，在弹窗中显示渠道编码、渠道名称和说明字段。

### 活动管理

- 页面主体是活动查询区和活动列表。
- 查询条件包括站点、渠道、状态和关键词。
- 右上角提供“新建活动”按钮。
- 点击按钮后，在弹窗中显示站点、渠道、活动编码、活动名称和说明字段。
- 活动编码继续执行小写英文字母、数字和连字符校验。

### 站点接入

- 保持现有页内配置表单。
- 不改为弹窗，不改变保存行为。

## 弹窗规范

- 使用居中的模态弹窗和页面遮罩，不使用抽屉或独立创建页面。
- 桌面端宽度约为视口的 75%，最大高度为视口的 85%。
- 内容超过最大高度时，仅弹窗内容区滚动，标题和操作区保持可见。
- 移动端宽度接近全屏，保留必要的页面边距，字段改为单列。
- 推广链接和活动表单在桌面端使用紧凑双列布局；跨列字段沿用现有字段语义。
- 渠道表单根据字段数量保持紧凑，不使用额外装饰或空白卡片填充空间。
- 弹窗包含标题、右上角关闭按钮、取消按钮和主要提交按钮。
- 支持右上角关闭、取消、Escape 和点击遮罩关闭。
- 关闭未提交弹窗时重置本次输入；创建失败时弹窗保持打开并保留输入。
- 创建成功后关闭弹窗、重置表单并刷新对应列表。
- 保存过程中禁用重复提交和关闭操作。

## 查询与数据流

- V1 继续一次性加载站点、渠道、活动和推广链接数据。
- 查询条件在前端对已加载数据进行组合筛选，不新增后端分页或查询接口。
- 切换页签保留各页面当前查询条件，页面刷新后恢复默认条件。
- 推广链接的活动查询选项受站点和渠道条件约束。
- 活动列表的渠道条件可以与站点条件组合使用。
- 关键词执行不区分大小写的包含匹配，并覆盖名称、编码及列表中已有的来源信息。

## 错误与空状态

- 初始数据加载失败继续使用现有错误面板和重试入口。
- 创建失败使用现有 Toast 错误反馈，弹窗不关闭。
- 查询无结果时显示“没有符合筛选条件的记录”。
- 尚未创建任何记录时显示对应的首次空状态，并保留新建按钮。
- 不直接向用户显示后端校验错误数组；前端已知约束在表单字段旁提前提示。

## 可访问性与响应式

- 页签继续使用 `tablist`、`tab` 和 `aria-selected` 语义。
- 模态弹窗使用 `dialog`、`aria-modal` 和可读标题。
- 打开弹窗后焦点进入弹窗；关闭后焦点回到触发按钮。
- 弹窗打开时页面背景不可交互。
- 所有字段保持可见标签，图标按钮提供可读名称。
- 在桌面和 375px 移动视口下不得出现页面级横向溢出、文本遮挡或操作按钮裁切。

## 技术边界

- 不修改 Growth 数据库结构、API 路由、请求 payload 或权限规则。
- 不增加编辑、删除、批量操作、服务端分页或分析指标。
- 复用现有 React 状态、API 调用、Toast 和 CSS 设计系统。
- 不引入新的前端依赖。
- 本设计替代上一版纵向工作台设计中“创建表单长期显示在列表上方”的页面结构，其余数据和行为约束继续有效。

## 验收标准

1. 顶部显示“推广链接 / 渠道管理 / 活动管理 / 站点接入”四个独立页签。
2. 推广链接、渠道管理和活动管理默认只显示查询区、列表与新建按钮。
3. 三个新建按钮分别打开居中的大弹窗，桌面端宽度约占视口四分之三。
4. 创建成功后弹窗关闭且列表刷新；创建失败后输入不丢失。
5. 原有推广链接渠道联动、活动编码校验和站点接入保存功能保持有效。
6. 聚焦渲染测试、完整前端测试和生产构建通过。
7. 桌面与 375px 移动视口下页面和弹窗无横向溢出、重叠或裁切。
