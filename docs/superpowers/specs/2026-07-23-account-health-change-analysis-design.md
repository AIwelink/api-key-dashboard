# 全部账号健康变化分析设计

## 目标

在“站点配置 > 实际额度检测”中增加全部账号分析，同时展示最近 1 天和最近 7 天。分析包含仍在使用、异常、封禁及已经从远端移除但窗口内曾被观察到的账号。

系统不再保存逐账号小时快照。不可用状态由现有 `remote_account_status_events` 的前后状态变化重建，账号观察范围、类型及最后一次额度数据来自 `remote_account_identities`。

## 不可用口径

以下情况合并为“不可用”：

- 401、Unauthorized、OAuth Token revoked/invalidated、Authentication failed、Refresh Token 失效；
- 明确的 banned、deactivated、suspended、封禁或停用；
- HTTP 502、Bad Gateway 或明确的上游 502。

以下情况不计入不可用：

- 5h/7d 429、rate limit、quota limit；
- 没有明确封禁信息的临时 403；
- 仅 `schedulable=false`、手动停止调度或手动禁用。

同一账号连续的不可用观察合并为一个区间。区间以恢复变化结束；仍未恢复的区间截止到统计时间，并计入“进行中”。同一次探测写出的状态、错误和 401 专项事件按账号和探测时间合并，避免重复计算。

## 指标

最近 1 天和最近 7 天均按同一口径计算：

- 不可用概率 = 窗口内至少进入一次不可用的唯一账号数 / 窗口内被观察到的唯一账号数；
- 平均不可用时长 = 窗口内所有不可用区间的裁剪后总时长 / 区间数；
- 不可用账号、区间及进行中区间数量；
- 平均 5h/7d 使用率；
- 平均 5h/7d 实际成本。

额度均值直接读取身份表已有的最后一次 `last_usage_snapshot`。缺失的数值不以 0 参与平均。结果提供总体统计，并按 free、plus、特殊 plus、team、特殊 team、bug team、k12、pro 和 unknown 分组。

## 数据与刷新

后端每个站点只保存一份派生分析结果，包含 1d 和 7d 两个窗口。结果最多每小时重算一次，每次使用 replace/upsert 覆盖旧结果；不保存账号明细或历史分析序列。前端静默刷新可重复读取缓存，不会重复执行统计。

状态事件和身份数据只查询最近 7 天需要的范围；更早数据不参与本功能。分析缓存设置短期 TTL，接口读取时会在缓存超过一小时后尝试刷新；页面现有的静默刷新会自然触发下一小时的计算。刷新失败时接口继续返回最近一次成功结果并标记为过期，且不会影响原实际额度检测。

## 接口与界面

`GET /api-pools/quota-detection?site_id=...` 保留原实际额度检测结果，并新增 `account_health_analysis`：

- `computed_at`、`next_refresh_at`、`stale`；
- `periods.one_day` 和 `periods.seven_days`；
- 每个周期下的 `overall` 与 `items`。

前端在现有实际额度表下增加“全部账号分析”，以账号类型为行、最近 1 天和最近 7 天为两列。总体统计置顶；无事件时明确显示样本不足，不把缺失数据计算为 0% 风险。

## 测试

- 分类测试覆盖 401、封禁、502，以及 429、临时 403、调度关闭的排除规则；
- 区间测试覆盖重复事件去重、恢复、跨窗口区间、进行中区间和观察时间裁剪；
- 聚合测试覆盖唯一账号概率、按类型统计、缺失额度值和 1d/7d；
- 服务测试覆盖一小时缓存、过期重算和失败回退；
- 路由与前端测试覆盖新增返回字段和渲染。
