# Growth 配置编辑功能设计

## 目标

在现有“推广链接 / 渠道管理 / 活动管理 / 站点接入”工作台中补齐编辑能力，使运营人员可以修正配置、调整状态和有效期，而不改变已经参与归因计算的编码与归属关系。

本次只建设现有 Growth 配置对象的编辑能力。个人邀请、推广主体、分成规则和佣金流水属于后续独立模块，不在现有推广链接字段中提前固化。

## 设计原则

- 列表继续承担查询与结果浏览，编辑使用与创建一致的居中大弹窗。
- 桌面端弹窗保持约四分之三视口宽度，移动端接近全屏并改为单列。
- 创建状态和编辑状态相互隔离；打开、取消或保存编辑不会污染创建表单。
- 已经决定归因身份的编码和外键只读，避免历史统计发生静默迁移。
- 编辑失败保留弹窗与当前输入，成功后关闭弹窗、清理状态并刷新四类工作区数据。
- 复用现有 PATCH 路由、Toast、权限和审计日志，不新增数据库表或前端依赖。

## 页面交互

### 推广链接

- 每条推广链接右侧保留复制和快速启停操作，并增加带可访问名称的编辑图标按钮。
- 点击编辑后打开“编辑推广链接”弹窗。
- 弹窗顶部用紧凑只读信息区展示链接编码、公开 URL、所属站点、渠道和活动。
- 表单按“来源归因 / 落地与有效期 / 扩展维度 / 状态”组织，不嵌套卡片。
- 保存按钮调用 `PATCH /growth/tracking-links/{tracking_link_id}`。
- 已归档链接仍可修改说明性字段，但状态保持归档，不能重新启用。

### 渠道管理

- 每条渠道记录增加编辑图标按钮。
- 点击后打开“编辑渠道”弹窗，并在顶部只读展示渠道编码。
- 保存按钮调用 `PATCH /growth/channels/{channel_id}`。

### 活动管理

- 每条活动记录增加编辑图标按钮。
- 点击后打开“编辑活动”弹窗，并只读展示活动编码、站点和渠道。
- 保存按钮调用 `PATCH /growth/campaigns/{campaign_id}`。

### 站点接入

- 保持现有页内表单，不再增加一层编辑弹窗。
- 切换站点时继续加载对应配置；点击“保存站点接入”执行现有 PUT 请求并刷新数据。
- 接入状态继续区分“已接入”和“未接入”，避免与客户站点业务数据库状态混淆。

## 字段边界

### 推广链接

可编辑字段：

- `source_type`
- `source_name`
- `source_url`
- `audience_group`
- `promoter`
- `landing_path`
- `extra_dimensions`
- `valid_from`
- `valid_until`
- `status`，但归档记录固定为 `archived`

只读字段：

- `tracking_link_id`
- `code`
- `public_url`
- `site_id`
- `campaign_id`
- 由活动派生的渠道归属

### 渠道

可编辑字段：

- `name`
- `description`
- `status`

只读字段：

- `channel_id`
- `code`

### 活动

可编辑字段：

- `name`
- `description`
- `starts_at`
- `ends_at`
- `status`

只读字段：

- `campaign_id`
- `code`
- `site_id`
- `channel_id`

### 站点接入

继续允许修改现有 `GrowthSiteUpdate` 中的公开域名、默认落地路径、用户绑定方式、时区、币种、同步间隔、初始同步时间和状态。客户站点 ID 与系统类型不在此页面修改。

## 前端状态与组件边界

- 保留现有 `createModal` 和三类创建表单。
- 新增独立的编辑目标状态，包含对象类型和记录 ID；弹窗数据使用专用编辑表单，不复用创建表单对象。
- 将记录转换为编辑表单的逻辑提取为纯函数，负责时间格式转换、扩展维度补齐和只读身份数据保留。
- 将编辑表单转换为 PATCH payload 的逻辑提取为纯函数，只发送允许修改的字段，不携带编码和归属字段。
- 继续复用 `GrowthCreateModal` 的对话框、焦点、Escape、遮罩和提交保护能力；组件名称可以保持不变，但标题与提交文案由调用方决定。
- 列表行操作保持稳定宽度，编辑按钮使用现有图标库中熟悉的编辑图标；若项目没有图标库，则使用当前设计系统的紧凑文字按钮，不新增依赖。

## 数据流

1. 用户点击列表行的编辑入口。
2. 页面根据当前已加载记录生成一份编辑表单快照。
3. 用户修改允许字段并提交。
4. 前端构造只包含可变字段的 PATCH payload。
5. 后端现有更新仓储执行更新并写入操作者与更新时间。
6. 路由写入现有审计日志。
7. 保存成功后刷新站点、渠道、活动和推广链接数据，并关闭编辑弹窗。
8. 保存失败时仅显示错误 Toast，编辑弹窗和输入保持不变。

## 校验与错误处理

- 名称等后端必填字段在前端提交前校验，避免发送空字符串。
- 来源 URL 继续接受空值或合法 HTTP/HTTPS URL。
- 落地路径继续要求站点相对路径。
- 活动起止时间和推广链接有效期必须满足结束时间晚于开始时间。
- 最多保留三个非空扩展维度键值，提交前进行 trim。
- 后端 404、409、422 和数据库不可用错误继续走统一 Toast 文案。
- 编辑期间禁止重复提交；保存期间禁止关闭弹窗。

## 邀请分成扩展边界

未来个人邀请和分成不复用 `promoter` 字符串承担主体、规则或账务语义。后续模块应独立建模：

- 推广主体：内部运营、合作伙伴、个人邀请人。
- 邀请关系：邀请人与被邀请账号的绑定及生效时间。
- 分成规则：比例、适用产品、有效期和结算条件。
- 佣金流水：由充值、退款和结算事件产生的不可变账务记录。

推广主体可以在后续通过新外键关联推广链接，邀请关系可以引用推广主体或邀请代码，佣金流水可以引用订单事实和归因结果。本次编辑表单按业务分区组织，以便未来增加推广主体选择器，但不预留无语义 JSON 字段，也不修改当前 Growth 数据库结构。

## 测试策略

- 纯函数测试覆盖三类记录到编辑表单及编辑表单到 PATCH payload 的转换。
- 静态渲染测试覆盖三类列表的编辑入口、弹窗标题、只读字段和可编辑字段。
- 交互状态测试覆盖创建与编辑状态隔离、取消重置、失败保留、成功关闭并刷新。
- 后端路由测试确认三个 PATCH 路由写入正确审计资源和更新结果。
- 后端仓储测试确认只更新 schema 允许的字段，找不到记录时返回明确错误。
- 完整前端测试、完整后端测试和生产构建必须通过。
- 桌面与 375px 移动视口检查弹窗无横向溢出、按钮裁切或内容遮挡。

## 验收标准

1. 推广链接、渠道和活动的每条列表记录都有清晰的编辑入口。
2. 三类编辑弹窗均预填当前数据，且编码与归属字段不能修改。
3. 各编辑表单只提交本设计列出的可变字段。
4. 保存成功后列表显示最新值；保存失败后输入不丢失。
5. 创建弹窗与编辑弹窗互不污染，关闭后再次打开得到服务器当前值。
6. 已归档推广链接不能通过编辑恢复为启用或停用。
7. 站点接入仍可在原页面修改并保存。
8. 不新增邀请人、分成规则或佣金字段，不改变现有归因关系。
9. 自动化测试、生产构建和桌面/移动视觉检查通过。

## 非目标

- 不允许修改编码、站点、渠道或活动归属。
- 不增加删除、批量编辑、批量归档或数据迁移功能。
- 不实现个人邀请、分成计算、佣金结算或财务报表。
- 不新增通用动态表单引擎或后台字段配置系统。
- 不改变 Growth 数据库表结构、权限模型或现有公开链接格式。
