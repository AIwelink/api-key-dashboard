# AIWeLink / AIGCLink 运营分析与内部人员设计

## 1. 文档状态

- 日期：2026-07-25。
- 状态：V1 设计已确认，可进入实施。
- 管理页面：现有“运营管理”。
- 首批站点：`aiwelink`（Sub2API/PostgreSQL）与 `aigclink`（NewAPI/MySQL）。
- 分析数据库：现有 Growth PostgreSQL。

## 2. 目标

运营管理页面需要统一回答：

1. AIWeLink、AIGCLink 最近的新增、活跃、调用、额度消耗、成本和收入情况。
2. 普通用户和内部人员分别产生了多少使用量、成本、额度和收入。
3. 额度来自支付、销售兑换码、推广、内部使用、补偿还是其他用途。
4. 哪些历史额度记录无法自动判断用途，需要运营人员补录。
5. 当前页面数据更新到什么时间，是否正在同步、延迟或失败。

## 3. 已确认决策

1. 用户只分为“普通用户”和“内部人员”，不建设测试账号配置。
2. 内部人员使用 `(site_id, external_user_id)` 唯一识别；邮箱、用户名只用于显示和搜索。
3. 内部人员的调用和消耗必须统计，但不进入普通用户收入、付费和转化指标。
4. 兑换码生成和管理员调额以后从运营管理页面统一发起，操作时必须选择用途。
5. 绕过运营管理页面产生且无法自动识别的兑换码或调额记录进入“待分类”，由运营人员补录。
6. 成功支付订单自动归为销售；销售兑换码按实际收款统计收入，不按额度面值统计收入。
7. 推广、内部使用、补偿和其他非现金额度收入为 0，但额度发放和消耗完整统计。
8. 运营页面不直接查询 AIWeLink/AIGCLink 业务库；后台提前同步并缓存到 Growth PostgreSQL。
9. 每 15 分钟增量同步；每次回扫最近 48 小时。
10. 最近 48 小时生成小时汇总，最近 30 天生成日汇总，管理接口再缓存 60 秒。
11. 默认时间范围为最近 7 天，提供今天、7 天、30 天和自定义时间范围，并显示同长度上期环比。
12. 跨站统一金额使用 CNY。
13. 站点换算比例独立配置并按生效时间版本化：AIGCLink 初始为每 1 CNY 对应 1 业务余额单位，AIWeLink 初始为每 1 CNY 对应 10 业务余额单位。
14. `owner/admin` 可执行配置和额度写操作；`operator` 只读运营数据并可触发立即刷新。

## 4. 非目标

V1 不做以下事项：

- 不把 Growth PostgreSQL 变成业务用户、支付、余额或调用事实源。
- 不修改 Sub2API/NewAPI 原始历史记录。
- 不复制密码、Session、API Key、访问令牌、请求内容或完整兑换码。
- 不直接向业务数据库写用户余额或兑换码。
- 不使用 AIWeLink 与 AIGCLink 不兼容的原始余额单位直接求和。
- 不实时查询业务数据库来渲染页面。
- 不建设超过 30 天的长期预聚合报表。
- 不在 V1 中建设测试账号、财务总账或会计对账系统。

## 5. 数据所有权

| 数据 | 权威来源 | Growth PostgreSQL 中的作用 |
|---|---|---|
| 用户与当前余额 | Sub2API/NewAPI | 最小化用户快照与分组查询 |
| 调用和消耗 | Sub2API/NewAPI | 标准化使用事实与汇总 |
| 支付订单 | Sub2API/NewAPI | 现金收入事实 |
| 兑换码与管理员调额 | Sub2API/NewAPI | 额度事实和来源关联 |
| 内部人员分类 | Growth PostgreSQL | 运营分类权威来源 |
| 用途补录 | Growth PostgreSQL | 分析分类，不改业务事实 |
| 换算比例 | Growth PostgreSQL | 历史版本化成本换算 |
| 小时/日汇总 | Growth PostgreSQL | 页面查询缓存 |

## 6. 统一术语与计算

### 6.1 用户分组

```text
命中 growth.internal_users → 内部人员
未命中                    → 普通用户
全部用户                  → 普通用户 + 内部人员
```

内部人员配置带生效时间。历史事实按事实发生时间匹配当时有效的内部人员记录，避免后续修改身份时无意改写过去口径。

现有 `growth.user_exclusions` 不参与本页面的用户分组，V1 不扩展其配置能力。

### 6.2 额度用途

正式用途枚举：

- `sale`：销售；
- `promotion`：推广；
- `internal`：内部使用；
- `compensation`：补偿；
- `other`：其他。

`pending` 是分类状态，不是正式用途。待分类记录不得进入按用途拆分的正式收入或额度指标，但仍保留在数据质量计数中。

### 6.3 额度来源

来源类型至少包括：

- `payment_order`；
- `redemption_code`；
- `admin_adjustment`；
- `subscription_order`；
- `other`。

来源和用途是两个维度。例如来源为 `redemption_code`，用途可以是销售、推广或内部使用。

### 6.4 金额和成本

业务系统中的 quota、balance 或 USD 命名字段统一称为“业务余额单位”，不能直接视作真实美元。

每条换算比例记录：

```text
balance_units_per_cny
```

计算方式：

```text
消耗成本 CNY = 消耗业务余额单位 / 事实发生时生效的 balance_units_per_cny
```

初始比例：

| 站点 | `balance_units_per_cny` |
|---|---:|
| `aigclink` | 1 |
| `aiwelink` | 10 |

比例缺失时保留原始消耗量，但跨站成本显示“未完整接入”，禁止用默认值猜测。

### 6.5 收入

- 成功支付订单使用订单实收 CNY。
- 销售用途兑换码使用运营人员填写的实际收款 CNY。
- 推广、内部使用、补偿和其他非现金额度的收入为 0。
- 额度面值不等于收入。
- 运营贡献为现金收入减消耗成本；内部人员单独显示内部成本。

## 7. 数据表

### 7.1 `growth.internal_users`

内部人员配置表：

| 字段 | 含义 |
|---|---|
| `internal_user_id` | UUID 主键 |
| `site_id` | 站点 |
| `external_user_id` | 业务用户 ID |
| `display_name` | 显示名称 |
| `email_snapshot` | 邮箱快照 |
| `department` | 部门或团队 |
| `note` | 备注 |
| `effective_from` | 生效时间 |
| `effective_until` | 失效时间，可空 |
| `status` | `active` 或 `inactive` |
| `created_by/updated_by` | 操作人 |
| `created_at/updated_at` | 审计时间 |

同一 `(site_id, external_user_id)` 的有效时间段不得重叠。

### 7.2 `growth.balance_conversion_rates`

| 字段 | 含义 |
|---|---|
| `conversion_rate_id` | UUID 主键 |
| `site_id` | 站点 |
| `balance_units_per_cny` | 每 1 CNY 对应余额单位，必须大于 0 |
| `effective_from` | 生效时间 |
| `effective_until` | 失效时间，可空 |
| `note` | 备注 |
| `created_by/created_at` | 审计字段 |

比例通过新增版本修改，不覆盖已用于历史事实的比例。

### 7.3 `growth.ops_user_snapshots`

保存运营查询所需的最小用户快照：站点、业务用户 ID、显示名、邮箱快照、注册时间、状态、当前余额、源更新时间和同步时间。不得保存认证或密钥字段。

### 7.4 `growth.credit_events`

统一额度事实：

| 字段 | 含义 |
|---|---|
| `credit_event_id` | UUID 主键 |
| `site_id/external_user_id` | 用户身份，未兑换批次可暂为空 |
| `source_type/source_record_id` | 业务来源与稳定 ID |
| `source_batch_id` | 本地生成批次，可空 |
| `purpose` | 正式用途，可空 |
| `classification_status` | `classified` 或 `pending` |
| `direction` | `credit` 增加或 `debit` 扣减 |
| `balance_units` | 增加或扣减的绝对额度，必须大于 0 |
| `cash_amount_cny` | 实际收款，非销售为 0 |
| `occurred_at/source_updated_at` | 业务时间 |
| `classified_by/classified_at` | 分类审计 |
| `note` | 备注 |

唯一键为 `(site_id, source_type, source_record_id)`。

### 7.5 `growth.redemption_batches`

运营页面生成兑换码的批次记录：站点、幂等请求 ID、数量、单码额度、用途、销售实收总额、备注、有效期、业务批次 ID、状态、成功数量、失败数量和审计字段。

Growth PostgreSQL 只保存兑换码掩码和不可逆哈希。明文只在生成成功响应中展示一次并允许当场下载。

### 7.6 `growth.balance_adjustment_requests`

运营页面调额请求记录：站点、外部用户 ID、幂等请求 ID、增加或扣减方向、额度、用途、销售实收金额、备注、业务操作 ID、状态、错误码和审计字段。

调额必须通过业务系统正式管理接口完成。若某站点版本没有可靠写接口，该站点显示“调额未接入”，禁止回退为直接更新业务数据库。

### 7.7 `growth.usage_facts`

统一到用户和时间桶的消耗事实，至少保存站点、用户、源记录 ID 或源时间桶、成功调用次数、消耗余额单位、换算比例 ID、消耗成本 CNY、发生时间、源更新时间和同步时间。

### 7.8 `growth.classification_tasks`

记录未识别用途的来源事实、建议分类、任务状态、补录结果和审计。一个来源事实最多存在一个未关闭任务。

### 7.9 汇总与同步表

- `growth.ops_hourly_stats`：最近 48 小时，按站点、小时、用户分组聚合。
- `growth.ops_daily_stats`：最近 30 天，按站点、日期、用户分组聚合。
- 复用或扩展 `growth.sync_cursors` 和 `growth.sync_runs` 保存适配器增量水位和运行结果。

汇总至少包含新增用户、活跃用户、成功调用、消耗余额单位、消耗成本、现金收入、付费用户、各用途额度发放和待分类数量。

## 8. 业务系统适配

### 8.1 AIWeLink / Sub2API

- 用户：`users`；
- 调用消耗：`usage_logs` 和现有聚合表；
- 支付：`payment_orders`；
- 兑换码：`redeem_codes` 及可关联兑换记录；
- 管理员调额：兑换码或调整关联记录。

### 8.2 AIGCLink / NewAPI

- 用户：`users`；
- 调用消耗：优先 `quota_data`，必要时用 `logs` 校验；
- 支付：`top_ups`、`subscription_orders`；
- 兑换码：`redemptions`；
- 管理员调额：管理操作日志。

两个适配器必须独立实现，不在统一查询函数中散布数据库类型判断。字段映射在连接真实生产版本后通过只读 Schema 探测和样本验证固化。

## 9. 同步和缓存

1. 后台每 15 分钟为每个启用站点执行增量同步。
2. 使用业务稳定 ID、更新时间和时间水位组合推进游标。
3. 每次回扫最近 48 小时，吸收迟到订单、退款、状态变化和管理员操作。
4. 标准化写入使用唯一键 UPSERT，重复同步不得重复计数。
5. 同步完成后只重算受影响的小时和日期。
6. 小时汇总只保留最近 48 小时；日汇总只保留最近 30 天。
7. 管理接口对相同查询条件缓存 60 秒。
8. 用途、内部人员或换算比例变更后，失效相关接口缓存并异步重算受影响窗口。
9. “立即刷新”只提交异步同步任务；同一站点已有任务运行时返回现有任务。
10. 页面请求不得等待远程业务库。

同步状态：

- 最近成功时间未超过 30 分钟：正常；
- 超过 30 分钟：数据延迟；
- 超过 60 分钟或连续失败：同步失败；
- 从未成功：未接入；
- 当前存在运行：同步中。

## 10. 页面设计

运营管理页使用顶部页签，不做左右分栏：

1. `运营概览`；
2. `内部人员`；
3. `兑换码与额度`；
4. `待分类`。

创建和编辑使用约页面宽度四分之三的弹窗。列表采用“查询条件 + 表格 + 弹窗操作”的结构。

### 10.1 运营概览

筛选：站点、时间范围、用户类型。默认最近 7 天，提供今天、7 天、30 天和自定义范围。

页面显示：

- 新增用户；
- 活跃用户；
- 成功调用次数；
- 消耗余额单位；
- 消耗成本 CNY；
- 现金收入 CNY；
- 付费用户；
- 非现金额度发放；
- 运营贡献；
- 同长度上期环比；
- 数据更新时间和同步状态。

趋势区显示收入与成本、新增与活跃、额度用途构成以及两站对比。指标可进入用户或事件明细。

### 10.2 内部人员

支持按站点、状态和关键词查询；显示用户身份、生效时间、当前余额、最近活跃、近 7/30 天消耗、额度来源和备注。`owner/admin` 可新增、编辑和停用。

### 10.3 兑换码与额度

显示兑换码批次和额度事件。生成弹窗字段：站点、单码额度、数量、用途、销售实收总额 CNY、客户或外部订单备注、有效期。

销售时实收金额必填且大于 0；其他用途实收金额固定为 0。

调额弹窗字段：站点、目标用户、增加或扣减、额度、用途、销售实收金额和备注。扣减操作的实收金额固定为 0。提交前必须显示目标用户和换算后的 CNY 影响供管理员确认。

### 10.4 待分类

显示站点、用户、额度、发生时间、来源系统、操作者和建议用途。支持批量补录；销售时必须填写实际收款金额。分类修改保留完整审计，不修改业务库原记录。

## 11. API

只读运营接口：

- `GET /operations/summary`；
- `GET /operations/trends`；
- `GET /operations/users`；
- `GET /operations/sync-status`；
- `POST /operations/refresh`。

配置和写操作：

- `GET/POST/PATCH /operations/internal-users`；
- `GET/POST /operations/redemption-batches`；
- `GET/POST /operations/balance-adjustments`；
- `GET/PATCH /operations/classification-tasks`；
- `GET/POST /operations/conversion-rates`。

所有响应必须区分真实零值、未接入、同步中、数据延迟和同步失败。列表接口支持分页、站点、状态、时间和关键词过滤。

## 12. 权限

| 能力 | owner/admin | operator |
|---|---:|---:|
| 查看概览、趋势和明细 | 是 | 是 |
| 查看同步状态 | 是 | 是 |
| 触发立即刷新 | 是 | 是 |
| 管理内部人员 | 是 | 否 |
| 配置换算比例 | 是 | 否 |
| 生成兑换码 | 是 | 否 |
| 调整额度 | 是 | 否 |
| 补录或修正用途 | 是 | 否 |

所有额度和分类写操作写入现有审计日志。

## 13. 失败处理

- 业务系统生成兑换码失败：批次标记失败，不伪造代码。
- 业务系统调额失败：请求标记失败，不在 Growth PostgreSQL 伪造余额变化。
- 网络超时：先按幂等请求 ID 对账，不直接重复生成。
- 部分成功：批次进入 `needs_reconciliation`，禁止盲目重试。
- 同步失败：继续显示上次成功缓存并标注时间与状态。
- 业务字段变化：适配器运行失败并告警，不把缺失值当 0。
- 换算比例缺失：保留原始消耗，跨站成本标记不完整。
- 用途待分类：保留额度事实和任务，不进入正式用途收入。
- 汇总重算失败：保留旧版本并标记缓存陈旧。

## 15. V1 验收

1. 配置 AIGCLink 比例 `1`、AIWeLink 比例 `10`。
2. 两站各配置一个内部人员。
3. 生成销售、推广和内部使用兑换码。
4. 对内部人员执行一次内部用途调额，并在 AIWeLink/AIGCLink 源记录中完成对账。
5. 普通用户和内部人员分别产生成功调用和消耗。
6. 普通、内部和全部三套数据准确且不重复。
7. 内部人员消耗进入成本，但不进入普通用户收入和付费指标。
8. 销售码按实收金额计收入，推广码和内部码收入为 0。
9. 绕过运营页面产生一条无法识别用途的额度记录，正常同步周期内进入待分类。
10. 补录后受影响小时和日期自动重算。
11. 页面不直接查询业务库；业务库故障时仍展示带更新时间的缓存。
12. operator 无法执行内部人员、换算比例、兑换码、调额和分类写操作。
13. owner/admin 的全部写操作可在审计日志中追溯。

## 16. 实施顺序
