# 当前一小时消耗速度设计

## 目标

在 API 账号池状态页的容量预估中增加“当前消耗速度”，以分组实际美元消耗为基础显示当前压力对应的 `$ / 小时`。该指标用于人工观察，不在本期改变容量健康等级、通知阈值或自动补号判断。

## 计算规则

所有时间判断使用 `Asia/Shanghai` 当前时间，并继续读取当前站点、当前分组的小时消耗数据，不能汇总站点内其他分组或客户端站点。

1. 整点后不足 5 分钟时，当前小时样本波动过大，显示上一个完整自然小时的实际消耗，单位 `$ / 小时`。
2. 整点后达到 5 分钟时，切换为本小时折算速度：`本小时累计消耗 / 本小时已过分钟 * 60`。
3. “上一个完整小时”必须是紧邻当前小时的自然小时；如果该小时数据缺失，不得使用更早小时冒充。
4. 达到 5 分钟后，如果本小时数据缺失，则显示无数据，不回退到上一小时。
5. 消耗和已过分钟必须为有效非负数；无效值返回无数据。结果保留现有美元格式所需精度，前端负责最终格式化。

边界定义：

- `00:00:00 <= elapsed < 00:05:00`：上一完整小时。
- `elapsed >= 00:05:00`：本小时折算。

## 后端字段

容量摘要新增：

```text
current_consumption_rate_usd_per_hour
current_consumption_rate_source
current_consumption_rate_elapsed_minutes
current_consumption_rate_hour
```

`current_consumption_rate_source` 只允许：

- `previous_full_hour`
- `current_hour_prorated`
- `unavailable`

`current_consumption_rate_hour` 表示实际采用数据所属的小时桶，便于排查数据延迟。无数据时速度和小时桶为 `null`，source 为 `unavailable`。

计算放在后端现有小时消耗摘要路径中，前端不得根据当前时间和累计消耗再次计算。

## 前端展示

在容量预估的核心实时指标区域、靠近“压力阶段”显示：

```text
当前消耗速度
$640/小时
本小时折算
```

整点后 5 分钟内的来源文案为“上一完整小时”，达到 5 分钟后为“本小时折算”。无数据时显示 `-` 和“等待小时消耗数据”。

标题提供悬浮说明，解释 5 分钟保护期和计算公式。沿用现有实时指标排版、颜色和数字刷新动画，不新增独立卡片，也不根据该值单独着色告警。

## 回测采样

现有每 5 分钟账号池容量样本增加上述速度、来源和小时桶字段。历史样本不回填；后续回测可区分上一小时值与当前小时折算值，不能把两种来源混为同一种预测输入。

## 异常处理

- 当前分组小时趋势请求失败时，容量页其他指标继续返回，当前消耗速度标记为无数据。
- 小时桶不连续、时间无法解析或当前小时累计为负数时，不使用该样本。
- 静默刷新只更新数字和来源，不重置页面滚动、筛选或展开状态。

## 测试范围

- 整点后 0、4 分钟使用上一完整小时。
- 整点后 5、30、59 分钟使用本小时折算。
- 上一小时缺失时不读取更早小时。
- 5 分钟后当前小时缺失时不回退。
- 跨日、跨月时仍正确识别紧邻的上一自然小时。
- 容量摘要、5 分钟样本和前端展示使用同一后端字段。
- 当前站点和分组隔离不受影响。
