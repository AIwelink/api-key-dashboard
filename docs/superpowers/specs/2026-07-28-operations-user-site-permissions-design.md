# 运营管理按用户站点权限设计

日期：2026-07-28

## 1. 背景

后台运营管理同时展示 AIWeLink 和 AIGCLink 数据。现有权限系统只按角色控制页面访问，拥有 operations-management 页面权限的用户可以读取全部运营站点，无法按人员限制站点范围。

本次增加个人级运营站点权限。权限仅作用于运营管理模块，不改变流量分析、客户站点、账号池等其他模块。

## 2. 目标

- 在现有权限管理页逐人配置 AIWeLink、AIGCLink 的运营访问权限。
- 未配置的用户默认没有任何运营站点权限。
- 前端只展示已授权站点。
- 后端对所有运营读写接口执行站点权限校验。
- “全部站点”只汇总当前用户已授权的站点。
- owner/admin 不自动获得站点权限，但仍可进入权限管理完成配置。
- 权限修改写入审计日志。

## 3. 非目标

- 不建立全系统通用的数据行级权限框架。
- 不修改流量分析、客户站点、账号池等页面的站点访问逻辑。
- 不按角色设置站点默认值。
- 不向 API Token 分配运营站点权限。
- V1 只支持 aiwelink 和 aigclink 两个站点。

## 4. 权限模型

用户文档增加 operations_site_ids 字段，值为去重后的站点 ID 数组。

允许的状态：

- []：无运营站点权限。
- ["aiwelink"]：仅 AIWeLink。
- ["aigclink"]：仅 AIGCLink。
- ["aiwelink", "aigclink"]：两个站点。

字段缺失、值类型错误或包含未知站点时，读取侧只保留合法站点；字段缺失等同空数组。保存接口拒绝未知站点，不静默保存无效值。

角色页面权限和个人站点权限相互独立：

- 角色未获得 operations-management：不能进入运营管理。
- 角色已获得 operations-management，但个人站点为空：可以进入页面，但只显示未分配权限的空状态。
- 两者同时满足：只能访问 operations_site_ids 中列出的站点。

## 5. 权限配置接口

新增：

GET /api/settings/operations-site-permissions

返回可配置站点和用户权限列表。用户项包含 user_id、email、name、role、status、operations_site_ids。用户列表按现有后台用户排序，禁用账号仍显示，便于提前调整权限。

PUT /api/settings/operations-site-permissions

请求提交完整用户权限映射。后端执行：

1. 校验调用者拥有 system-management 页面权限，因此仅 owner/admin 可操作。
2. 校验每个用户 ID 存在。
3. 校验站点 ID 仅为 aiwelink 或 aigclink。
4. 对站点数组去重并按固定顺序保存。
5. 使用批量更新写入用户文档。
6. 记录修改前后值到审计日志。
7. 返回保存后的完整配置。

如果提交期间用户已被删除，返回 409，前端保留未保存选择并提示刷新后重试，避免部分保存。

## 6. 运营接口执行规则

增加统一的运营站点权限解析与校验函数，所有 /api/operations 路由复用，避免各接口自行判断。

读接口：

- 显式请求 site_id 时，站点不在当前用户权限中返回 403。
- 未传 site_id 时，把允许站点数组传入 service 和 repository，只查询授权集合。
- 当前用户没有允许站点时返回 403，不允许空权限退化为查询全部。
- summary、trends、users、sync-status、internal-users、conversion-rates、classification-tasks 均执行相同过滤。
- 缓存键包含授权站点集合，防止不同权限用户复用越权缓存结果。

写接口：

- refresh 只能刷新授权站点；未传 site_ids 时只刷新授权站点。
- 创建内部人员、换算比例、兑换码和余额调整时，payload.site_id 必须已授权。
- 更新内部人员或待分类记录时，资源所属 site_id 必须已授权。
- 原有 owner/admin 写权限规则保持不变；站点权限是额外条件。

API Token actor 没有 operations_site_ids，按空权限处理。

## 7. 查询层调整

现有 repository 只接收单个 site_id。调整为接收 allowed_site_ids，并保留可选的显式 site_id：

- 显式站点已在路由层验证后，查询使用单站点集合。
- “全部站点”查询使用当前用户授权集合。
- PostgreSQL 条件统一使用 site_id = ANY(:allowed_site_ids) 或等价的参数化集合查询。
- 禁止用 NULL 表示全部站点，防止遗漏校验时扩大数据范围。

汇总、趋势、账号、同步状态及配置列表都必须使用同一站点集合语义。

## 8. 前端设计

在现有权限管理页的角色权限区域下方增加“运营站点权限”表格：

- 每行一个后台用户。
- 固定信息列：用户名称、邮箱、角色、状态。
- 权限列：AIWeLink、AIGCLink，使用复选框。
- 区域右上角提供独立的“保存站点权限”按钮。
- 显示“未勾选即无法查看该站点运营数据”的简短说明。
- 有未保存修改时暂停权限配置自动刷新，避免覆盖本地选择。
- 保存成功后使用服务端响应覆盖本地状态。
- 保存失败时保留选择并展示错误。

运营管理页从 /auth/me 读取 operations_site_ids：

- 无权限时显示独立空状态，不发起运营业务请求。
- 站点选择器只列出授权站点。
- “全部站点”表示全部已授权站点。
- 当前选择因权限刷新而失效时，自动切换到“全部站点”。

## 9. 兼容与上线

- 不执行存量授权迁移。
- 现有用户字段缺失时默认无权限。
- 发布后 owner/admin 先进入权限管理，为需要访问运营页的人员逐一授权。
- 权限保存后，下次 /auth/me 刷新即可生效；运营接口每次请求读取当前数据库用户，不依赖登录令牌中的旧权限。
- 撤销权限立即对后端接口生效。

## 10. 测试

后端测试覆盖：

- 字段缺失默认空权限。
- 配置接口仅 owner/admin 可用。
- 保存时去重、拒绝未知站点和未知用户。
- 单站点用户不能读取另一个站点。
- 双站点用户可读取两个站点。
- “全部站点”只向 repository 传递授权集合。
- 空权限用户访问运营接口返回 403。
- 读接口、刷新和配置写接口都执行站点校验。
- API Token 默认无权限。
- 权限修改生成审计记录。

前端测试覆盖：

- 权限表格按用户渲染两个站点复选框。
- 切换权限只修改目标用户。
- 保存提交完整映射。
- 空权限运营页显示权限提示且不加载业务数据。
- 单站点用户只看到对应选项。
- 回归验证原有角色页面权限不受影响。

## 11. 验收标准

1. 新部署后所有现有用户的运营站点权限均为空。
2. owner/admin 可以在权限管理页逐人勾选 AIWeLink、AIGCLink 并保存。
3. 只授权 AIWeLink 的用户无法通过页面或直接接口读取 AIGCLink 运营数据。
4. 同时授权两个站点的用户可以分别筛选，也可以查看仅包含这两个授权站点的汇总。
5. 撤销权限后，无需重新登录，后端立即拒绝对应站点请求。
6. 角色页面权限和个人站点权限继续独立生效。
