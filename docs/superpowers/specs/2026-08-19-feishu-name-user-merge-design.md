# 飞书姓名自动合并设计

## 目标

飞书扫码登录后，使用飞书返回的姓名识别现有本地用户。系统不使用邮箱作为自动绑定依据。

## 行为

- 只在登录流程中使用姓名匹配；密码登录后的手动绑定仍绑定当前已认证用户。
- 比较前去除姓名首尾空格，然后与本地 `users.name` 精确匹配。
- 候选必须同时满足：用户处于启用状态、未被合并、没有已绑定的飞书身份。
- 只有一个候选时，直接把飞书身份绑定到该用户，并记录 `bound_via=feishu_name`。
- 多个同名候选时不自动绑定，继续创建或保留待授权飞书用户，并记录歧义审计事件。
- 如果飞书身份此前已经自动创建为待授权用户，例如当前的“张可真”飞书账户，后续登录按同样的唯一姓名规则，将该源用户软停用并关联到原有本地账户，保留历史记录。
- 现有按飞书身份解析、待授权恢复、登录票据和权限校验逻辑继续有效。

## 数据与安全

- 不改变现有 `feishu_identity.identity_key` 唯一约束。
- 姓名匹配只作为身份未绑定到正式账户时的候选解析，不覆盖已绑定的其他飞书身份。
- 自动合并通过原子更新完成，避免并发登录产生双重绑定。
- 审计记录不包含邮箱、open_id、union_id、授权码或票据等敏感值。

## 验收标准

1. 本地用户“张可真”未绑定时，飞书用户“张可真”登录后直接进入原有本地用户。
2. 飞书姓名和本地姓名首尾存在空格时仍能唯一匹配。
3. 飞书邮箱与本地邮箱相同但姓名不同，不会按邮箱自动绑定。
4. 同名本地用户超过一个时不自动绑定。
5. 已存在的待授权飞书用户可按唯一姓名合并到本地用户，源用户保留为禁用历史记录。
6. 原有飞书身份登录和密码绑定流程继续通过。
