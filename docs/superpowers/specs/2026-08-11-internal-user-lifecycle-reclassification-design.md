# 内部人员生命周期与运营数据重分类设计

## 目标

完善运营管理中的内部人员新增、编辑和删除能力，并确保内部身份变化会立即、准确地反映到运营概览和历史趋势中。

运营概览默认展示普通用户，内部人员不进入默认正式运营数据；仍保留“全部用户”和“内部人员”筛选用于核对。

## 业务语义

### 新增

- owner/admin 按站点和邮箱新增内部人员。
- 邮箱唯一匹配业务账号时立即显示“识别成功”，并绑定业务用户 ID。
- 识别成功后，该账号全部历史调用、注册、付费和收入数据归入内部人员。
- 尚未匹配时保持“待识别”，后续同步发现唯一账号后自动完成绑定和重分类。

### 编辑

- owner/admin 可以修改邮箱、标记原因、生效时间和失效时间。
- 修改邮箱时解除旧账号绑定，再按新邮箱重新识别。
- 修改有效期后重新计算当前内部身份，并重算对应站点的历史运营聚合。
- 生效时间和失效时间控制配置是否有效；已确认的内部账号在配置有效时按账号身份进行历史重分类。

### 删除

- 删除用于纠正误添加，不用于表示离职或身份正常结束。
- 删除前显示二次确认，明确提示历史运营数据将重新计算。
- 删除时先解除用户快照的内部身份，再物理删除内部人员配置。
- 删除后，该账号全部历史数据重新归入普通用户。
- 删除前的完整记录保存在管理面板审计日志中。
- 正常身份结束通过编辑失效时间完成，保留历史内部身份记录。

## 后端设计

### 事务边界

新增、编辑和删除分别在一个 Growth PostgreSQL 写事务内完成：

1. 获取站点级运营同步事务锁。
2. 创建、修改或删除内部人员配置。
3. 更新 `growth.ops_user_snapshots` 的 `is_internal` 和 `internal_user_id`。
4. 重建该站点小时与日运营聚合。
5. 提交事务。
6. 清理对应站点的运营接口缓存。

任一步骤失败时整笔事务回滚，不能出现配置与聚合数据不一致。

### 历史聚合

内部人员配置变化频率低，正确性优先。识别成功、重新绑定或删除时，重算对应站点的完整历史小时和日聚合，而不是只回算同步任务默认的 48 小时窗口。

顶部汇总与站点对比继续查询事实表和用户快照；趋势继续读取缓存聚合表。两类数据在事务提交后应保持相同的用户分群结果。

### 缓存失效

当前缓存键把授权站点集合存为元组。按站点失效时必须同时检查嵌套站点集合，确保单站点和多站点查询都被清除。

### 删除接口

- 新增 `DELETE /api/operations/internal-users/{internal_user_id}`。
- 仅 owner/admin 可调用。
- 必须验证目标记录所属站点在操作者的 `operations_site_ids` 权限范围内。
- 成功返回被删除记录的安全字段，供审计日志写入。
- 不存在返回 404，无站点权限返回 403，数据库失败保持现有统一错误映射。

## 前端设计

- 运营概览初始用户群体改为“普通用户”。
- 权限范围变化时重置查询，也默认回到“普通用户”。
- 内部人员表格保留“编辑”，新增删除图标按钮和工具提示。
- 点击删除后打开确认弹窗，展示站点、邮箱和历史重算警告。
- 删除成功后关闭弹窗、刷新内部人员列表，并在下次进入运营概览时获取新数据。
- operator 继续只读，不显示新增、编辑和删除控件。

## 审计

- 新增和编辑沿用现有审计行为。
- 删除写入 `operations.internal_user.delete`。
- 审计资源类型为 `operations_internal_user`，资源 ID 为 `internal_user_id`。
- `before` 保存删除前记录，`after` 记录删除结果，不记录数据库连接信息等敏感配置。

## 测试与验收

### 后端

- 新增已识别人员会调用完整历史聚合重建并清理嵌套站点缓存。
- 编辑邮箱会解除旧绑定、绑定新账号并重建聚合。
- 删除会清除快照绑定、删除配置并重建聚合。
- 删除不存在记录返回 404；越权站点返回 403；operator 返回 403。
- 聚合失败时删除事务回滚。

### 前端

- 运营概览默认请求包含 `segment=ordinary`。
- owner/admin 可见新增、编辑和删除操作。
- operator 看不到写操作。
- 删除确认弹窗包含历史数据重算提示。

### 业务验收

1. 在普通用户概览中记录一个测试账号的历史调用数据。
2. 将该邮箱新增为内部人员并确认识别成功。
3. 普通用户顶部汇总、站点对比和趋势均不再包含该账号，内部人员筛选能够看到其数据。
4. 删除该内部人员配置。
5. 普通用户顶部汇总、站点对比和趋势重新包含该账号。
6. 审计日志可以查到新增和删除记录。
