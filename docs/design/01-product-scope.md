# Product Scope

## 背景

团队持有多个 OpenAI API key 或 ChatGPT OAuth 账号凭据，需要统一管理，并与 sub2api 保持同步。当前手工维护容易出现重复上传、过期未暂停、并发和优先级不一致、变更不可追溯等问题。

## 第一阶段目标

MVP 需要覆盖：

- 团队登录和基础权限控制。
- 后台用户管理，由 Owner 或 Admin 添加用户；不开放公开注册。
- 添加、编辑、删除、搜索账号。
- 记录每个上传账号的上传人、修改人、支付类型、邮箱和接码 session、原始 JSON、人工状态标注和备注。上传人和修改人自动绑定当前登录用户。
- 支持单个账号和批量 JSON 导入。
- 保存账号的期望状态，例如启用状态、并发、优先级、过期自动暂停。
- 连接 sub2api 获取账号状态、已使用额度和最后请求时间。
- 对接 sub2api，支持手动同步和自动同步。
- 查看 sub2api API 账号池状态，包括 groups、账号调度状态、5h/7d 用量窗口和总体容量。
- 展示同步结果、错误信息和最近操作记录。
- MVP 阶段账号 JSON 和管理信息直接明文保存到 MongoDB，后续如有需要再增加字段级加密。

## 暂不做或后置

- 多租户商业化计费。
- 复杂审批流。
- 多地域容灾。
- 大规模实时状态推送。
- Redis 队列和分布式锁，除非后续确定需要多实例部署。

## 用户角色

系统不开放公开注册。所有团队成员必须先由后台管理员创建账号，或后续通过受控邀请加入。

### Owner

系统最高权限。可以管理团队成员、系统配置、sub2api 连接和所有账号。

### Admin

可以管理账号、批量导入、执行同步、查看审计日志。

### Maintainer

可以新增和更新账号，可以执行手动同步，但不能查看完整密钥，不能修改系统级配置。

### Viewer

只读角色。只能查看账号信息、状态和同步结果；是否能查看完整凭据可后续按权限细化。

## 核心业务流程

### 添加后台用户

1. Owner 或 Admin 在后台创建用户。
2. 输入邮箱、姓名、角色和初始状态。
3. 系统生成临时密码或一次性设置密码链接。
4. 用户首次登录后必须修改密码。
5. 写入审计日志。

### 添加账号

1. 用户选择账号类型：`api_key` 或 `oauth`。
2. 输入基础信息和敏感凭据。
3. 后端校验字段。
4. 账号 JSON 明文保存到 `account_json`，管理字段保存到 `metadata`。
5. 写入审计日志。
6. 可选择立即同步到 sub2api。

### 批量导入

1. 用户粘贴或上传 JSON。
2. 后端解析并识别账号。
3. 系统生成导入预览，包括新增、更新、冲突和错误。
4. 用户确认后执行导入。
5. 每个账号写入导入结果和审计日志。

### 同步到 sub2api

1. 系统读取本地账号期望状态。
2. 查询 sub2api 当前状态。
3. 计算差异。
4. 生成同步计划。
5. 执行创建、更新、暂停、删除等操作。
6. 保存同步事件和错误详情。

### 查看 API 账号池状态

1. 前端从后端读取已配置 sub2api 站点。
2. 后端从 MongoDB 缓存返回 groups 和账号调度状态。
3. 用户可点击“同步账号池数据”触发远程 sub2api 到统一 MongoDB 缓存的同步。
4. 用户可点击“前端数据刷新”只重新读取 MongoDB 缓存。
5. 页面展示每个 group 的账号表、5h/7d 用量窗口和只计算健康可调度账号的总体容量。
